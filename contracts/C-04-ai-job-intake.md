# C-04 — AI 조사 작업 접수

> **C-04 란** 플랫폼이 AI 서버에 조사를 맡기는 약속이다.
> 번호 체계는 [계약 지도](README.md#번호가-무슨-뜻인가) 참고.

- **방향** Spring Boot P3 `investigation` → P4 `ai-server`(FastAPI)
- **방식** 외부 HTTP — **`POST /internal/ai/jobs`**
- **검증** T-04(자동·수동 시작) · T-06(중복·장애 복구)
- **상태** **기본 원칙 채택** — 필드·인증 헤더는 구현 전 고정한다

---

## 1. Request

| 필드 | 뜻 |
|---|---|
| `jobId` | **P3 가 먼저 저장한** 조사 요청 ID |
| `caseId` | 조사 사건 ID |
| `tenantId` | 조사 대상 고객사 |
| `requestOrigin` | `SYSTEM`(자동) 또는 `STAFF`(직원 요청) |
| `evidenceBasis` | 조회할 증거의 기준 범위 |
| `policyVersion` | 조사 조건·요청 정책 버전 |

## 2. Response

| 필드 | 뜻 |
|---|---|
| `jobId` | 접수한 작업 ID |
| `runId` | 실제 실행 추적 ID (발급했을 때) |
| `status` | `ACCEPTED` 등 접수 상태 |
| `acceptedAt` | 접수 시각 |

## 3. 처리 규칙

- **접수 성공(202)은 보고서 생성 완료가 아니다.**
- 같은 `jobId` 로 다시 요청하면 새 작업을 만들지 않고 **기존 접수 상태를 반환**한다.
- P3 가 요청을 **저장하고 트랜잭션을 끝낸 뒤** FastAPI 로 전달한다.
- FastAPI 의 접수 상태를 **재시작 후에도 확인할 수 있는 영속 기록**과 연결한다.
  실패·중단 시 P3 의 미처리 Job 으로 복구한다.

> `jobId` 를 플랫폼이 먼저 만들어 저장한 뒤 보내는 것이 이 계약의 핵심이다.
> AI 서버가 ID 를 만들면, 전달이 실패한 순간 플랫폼에 흔적이 남지 않는다.
