# 계약 지도

담당자끼리 주고받을 데이터의 약속이다. **이 폴더가 정본이다.** Notion 에는 링크만 둔다.
코딩 에이전트가 Notion 을 읽지 못하기 때문이다.

## 번호가 무슨 뜻인가

문서 곳곳에 번호가 나온다. 외우지 말고 여기서 찾아보면 된다.

| 번호 | 뜻 | 예 |
|---|---|---|
| **C-xx** | **계약**(Contract) — 담당자끼리 주고받을 데이터의 약속 | C-01 ~ C-07 |
| **T-xx** | **테스트**(Test) — 무엇이 통과해야 완성인지, 합격 기준 | T-01 ~ T-15 |
| **D-x** | **결정 대기**(Decision) — 사람이 정해야 진행되는 것 | D-1, D-2 |
| **P1~P6** | 담당자 구분 | P2 = 정후 = `risk` |
| **ADM / SEC / MER** | 화면 — 플랫폼 운영자 / 보안 직원 / 쇼핑몰 운영자 | SEC-01 |
| **ADR-xxx** | 아키텍처 결정 기록 — 왜 그렇게 정했는지 (Notion) | ADR-003 |
| **FIX-xx** | 아직 채택하지 않은 설계 개선 후보 (Notion) | FIX-07 |

번호를 쓸 때는 **처음 나올 때 한 번 풀어서 적는다.** "C-03" 말고
"C-03(경보를 사건으로 넘기는 약속)" 처럼 쓴다.

계약을 바꾸는 사람이 **같은 PR 에서 이 폴더도 고친다.** 별도 동기화 담당은 없다.

## 모든 계약에 공통

1. **고객사 격리** — 요청의 `tenantId` 만 믿지 않는다. 로그인 계정과 권한으로 확인한다.
2. **멱등성** — 같은 이벤트·요청이 두 번 와도 금액이나 사건이 두 번 생기지 않는다.
3. **전달 ≠ 완료** — 이벤트를 보냈다는 것과 받는 쪽이 끝냈다는 것은 다르다.
   내부 이벤트에는 HTTP 202 를 쓰지 않는다.
4. **트랜잭션** — 저장과 발행 기록은 한 트랜잭션. 원격 호출은 **항상 커밋 이후**.
5. **실패 구분** — 빈 데이터 / 업무 오류 / 외부 서버 오류 / 타임아웃은 서로 다른 의미다.
